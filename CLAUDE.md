## Multi-session parallelism discipline (rules established after the 2026-07-10 incident)
- Multiple CC sessions may be working in this repo at the same time. **The second and subsequent sessions must use `git worktree` isolation to change code**; sharing the same checkout for writing code is forbidden.
- If you really must work in the main checkout: first run `git branch --show-current` to confirm where you are; before switching branches/switching back to master, run `git log --oneline -3` to confirm you are not carrying away or leaving behind someone else's commits.
- Incident record: two agents shared a checkout; one switched branches to work, and the other's commits landed unnoticed on its branch, creating a "code disappeared" illusion when switching back (recovered with zero loss via reflog).
- Before committing, run `bash scripts/check_invariants.sh` (red-line machine checks: hook copies in sync / no leftover copies / version lockstep / dual dist consistency / venv ban / README numbers match measured values / ruff gate / hook registration surface unified / MCP tool parameter descriptions / table sets consistent — the script's output is authoritative for the item list and details).

## Deliberate decisions — do not quietly revert
The following designs **look anomalous but are all intentional** (each has a hard-luck history or machine-check backing); when you feel the urge to "fix" one, stop first:
- **Venv ban**: the four process types share dependencies; stick to the system Python + sys.executable (I5 machine check; the isolation approach has been rejected)
- **Multiple hook copies**: same-named files in plugin/hooks and src/aiteam/hooks must be byte-for-byte identical (I1 machine check) — this is not duplicated code, do not "deduplicate" it; changing one place means syncing all copies
- **tasks.config.memo is a frozen archive**: after memory v2 moved to tables, new memos only go into the task_memos table, and the old JSON is kept as history — it is not dirty data; do not clean it up and do not write to it again
- **Tool counts/page counts in the README** are machine-checked by I6 against measured values — do not manually "revert" them to old values; when adding or removing MCP tools, sync the README
- **Model defaults left empty (DB observation fields only)**: if agents.model is unknown, leave it empty for observation to backfill; do not fill in a specific model (hardcoding inevitably goes stale; rule established 2026-07-07). Note this does **not** refer to template frontmatter — plugin/agents/*.md has pinned the tier-level alias `model: opus` (ruled 2026-07-10; a floating alias does not count as hardcoding); dispatch discipline is in the orchestration charter: Fable orchestrates, Opus executes, and workflow `agent()` explicitly defaults to `model:'opus'` (skill /os-workflow §3)
- **No timers/background daemons**: CC is not resident; periodic cron has been deliberately retired — use on-demand tools for everything; do not "add back" scheduling

## Engineering pitfalls (rules established from hard evidence; run through them before writing tests)
- **Stubs must not be looser than production**: test doubles must reuse production validation (such as enum/schema validation), or unit tests will all be green while the production API rejects the input
- **Assertions must cross the persistence boundary**: a response assembled from in-memory objects "having values" does not count; you need cross-request database-checking idempotency cases to catch missing fields
- **Test assembly must be swapped as a set**: dependency singletons each hold their own repository; replacing only half of them makes tests write to the real database and read from the in-memory one, causing false round-trip failures
- **Put machine-check work at the front of the batch**: counts/anchors first, catch every drift on the spot, do not hoard it all to the end
- **Before deleting data, ask "can it be rebuilt if deleted"**: retention gates easily only ask "who will still come and look at this record", missing "would deleting it destroy data that can never be collected again". For every new deletion path, ask item by item whether the object being deleted carries derived data whose external source has expired and which exists only in this one copy (token accounts, parse artifacts, observation snapshots). Take the criterion broadly: if it was measured, it counts as having an account, and measuring 0 is also a measurement result. Record: two days after the container-team cleanup shipped, the five token columns had only just landed on the agents rows, the retention gate had never gone back to patch that up, and one empty shell carrying 85.41 million tokens was four hours away from entering deletion range (a6ccb67 patched the gate)
- **Before restoring from an old backup, ask about the clock convention**: restoring = writing a historical snapshot into the current database, and the two may be on two different clocks (before/after the UTC shift). The criterion must be machine-checked: compare `PRAGMA user_version`; if they differ, convert explicitly (reuse the same LOCAL_COLUMNS/shift_for as the shift script); abort on any unknown combination; comparing source and database by schema only, not content, cannot catch this class. Record: the 07-28 backup was in local wall-clock time; copying the forensic plan's restore verbatim would have stuffed 843 rows of +8h timestamps into the UTC database, afterwards indistinguishable from the true values (0faacd8's three-source structure + clock gate stopped it)

## When using CC Workflow (ultracode)
- The OS does not block Workflow; it positions itself as Workflow's persistent governance layer. Every Workflow run is **automatically tracked by a hook as a team** (`workflow-<wf_id>`); tracking is automatic.
- But the Leader still needs to: ① put the overall task on the wall with `task_create`; ② embed a "write-back instruction" in each workflow agent's prompt so it keeps its accounts with OS tools (task_memo_add/report_save).
- The standard template is in the **/os-workflow** skill (the hook also gives a soft reminder when Workflow is invoked).
